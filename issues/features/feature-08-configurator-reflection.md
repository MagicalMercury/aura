# 【"#" 配置器 + 反射机制】[ ] **主标题：统一配置器语法族（注解）+ 编译期元数据注册表 + 反射查询**

> **一句话摘要**：引入 `#` 前缀配置器语法族的**注解侧**——`#type` 声明元数据 schema、`#X{...}` 注解在声明上（挂载），元数据进**编译期生成的静态注册表**，标准库提供反射查询 API（`reflect.collect`），支撑 EventFuncCollector 等框架模式（「声明即注册」）。
>
> **语法一律以 v0.3 为准**（`plan/hash-metadata-requirements.md`，本文只引用、不重复定义）：配置器定义（§4.1）、元数据构造（§4.2）、挂载与相邻规则（§4.3）、挂载后果由实体类型决定（§4.4）、`where` 挂载点约束（§5）、`Code` 三位置与三×三值注入表（§7.4 / §7.6.5）、reflect 库与零成本（§9）。本文正文**只保留 v0.3 已定义的形态**；与 v0.3 有差异 / 未定义的形态（**D-06** 运行时分发守卫 / **D-07** 运行时线程标记 / **D-08** 运行时线程上下文语义 / **D-09** 裸符号作字段值 / **D-19** L1 声明式动作宏路线）已移出，集中登记于 `plan/hash-v0.3-feature-deltas.md`。本文保留**实现层内容**：背景动机、当前状态与缺口、依赖与前置条件、实现方案与分解步骤、验收清单、D1/D3/D4/D5 决策速记。

## 1. 背景与动机（Why）

- **业务/用户场景**：
  - **事件框架**：`#SubscribeEvent{ event = "PlayerJoin" }` 注解处理函数，启动期由收集器统一注册到事件总线（Minecraft mod 式开发体验）；
  - **框架注册声明化**：序列化注册、插件发现等「手工调用 `register(...)`」样板，改为「声明即注册」——注册信息写在声明头顶上，漏写不存在。
- **当前短板**：
  - 无任何注解/元数据语法——事件订阅、序列化注册等框架模式只能靠手工调用 `register(...)`，样板代码多且易漏；
  - 无反射查询——函数/type 的元数据（含名字）在编译后全部丢失（TypeDescriptor 仅含 GC 布局信息：size/ptrFieldOffsets 等，runtime/types.h:107-122）。
- **预期收益**：一个 `#` 配置器语法内核（`#type` schema + `#X{...}` 注解 + 静态注册表）覆盖元数据登记与反射查询；框架注册从「用户手写」变「声明式」；注册表由 CodeGen 静态生成，零运行时收集成本。

### 2.1 配置器定义（`#type`）——引用 v0.3 §4.1

> **语法以 v0.3 §4.1 为准**；本节不重复定义，只给落位指针。L0 级的规范级引用清单另见 [[feature-09-annotator]] §2.1。

- **`#type` = 编译期类型定义**（v0.3 §1.2 五档之「**定义标记**」：实体只存在于编译期；v0.3 §4.1）：字段（类型 + 默认值）、**值域必须落在编译期值域**、**字段值必须是编译期常量**。
- **不是 record**：不分配 GC、不进 `desc`、不参与运行期类型系统（v0.3 §4.1）。
- **相关条款**：元数据构造 `#X{...}`（§4.2）· 挂载 / 相邻规则 / 多条叠加 / 同配置器重复报错 / 不递归（§4.3）· 挂载后果由实体类型决定（§4.4）· `#type` 的方法（§4.5）· 当值来用 `#const`（§4.6）· 编译期类型的边界（§4.7）。
- **与 record 的关系（本 feature 决策 D5）**：配置器 = **独立 AST 节点**（ConfigTypeDecl），**不复用 record 通道**——配置器实例不分配 GC 堆（编译期数据），`desc`/GC 全链不感知（与 v0.3 §4.1「编译期类型不是 record」一致）。

### 2.2 应用形态：注解与挂载——引用 v0.3 §4.3 / §4.4 / §7.4 / §7.6.5

> **挂载判定以 v0.3 §4.3（相邻规则）/ §7.4（三×三位置表）/ §7.6.5（`#c` 用于挂载）为准**；形态骨架以 v0.3 §3.1 为准。本 feature 的应用面即「注解」——完全落在 v0.3 挂载语义内。

```aura
// 注解（Java 风格）：挂声明，元数据进静态注册表（v0.3 §4.2 构造 + §4.3 挂载）
#SubscribeEvent{ event = "PlayerJoin" }
fun (self Player) on_player_join(msg: string) { ... }
```

- **注解 = 元数据构造紧跟声明（挂载）**：`#X{...}`（或展开后等价形态）**紧跟**一条声明 ⇒ **挂载**（登记元数据）；出现在**表达式或 `#const` 初值位置** ⇒ **独立值**；两者都不是 ⇒ **禁止**（v0.3 §4.3）。
- **可挂载点** = 「有名字的声明」（v0.3 §4.3）：`type`（record）· `fun` · 方法 · `interface` · `#type` · `#fun`。
- **挂载后果由实体类型决定**（v0.3 §4.4）：`#type` 构造 `#X{...}` ⇒ **只登记**一条元数据，不执行行为；`#fun` 返回 `Code` 的 `#X(...)` ⇒ **编译期执行并织入**；**挂载点的 `#fun` 必须返回 `Code`**，非 `Code` ⇒ **编译错误**。
- **注解目标校验 = v0.3 §5 `where`**：`#type` 定义后的 `where { ... }` 限定「元数据能挂在哪」（如 `where { fun, method }`），**挂载时**检查；非法挂载点干净报错。
- **多条叠加允许**（`#A{...} #B{...} fun f()`）；**近声明者先应用**；**同一声明挂同一配置器两次** ⇒ **编译错误**；**不递归**（织入产物中新出现的 `#` 只登记元数据，v0.3 §4.3）。
- **`#c` 用于挂载（v0.3 §7.6.5）**：`#c` 展开后必须是 `#X{...}`（元数据构造 ⇒ 登记）或 `#X(...)`（`Code` 型调用 ⇒ 织入）才算挂载形态，其它 ⇒ **编译错误**。
- **值注入位置语义（v0.3 §7.4 三×三表）**：`#c` / `#{}` 的值按「**值类型 + 所在位置**」铺开——**表达式位置 = 值** / **语句位置 = `Code` 注入** / **声明前 = 挂载**；`Code` 值**禁止**出现在表达式位置（规则 4）。完整表以 v0.3 §7.4 为准（本文不转抄）。
- **字段值必须是编译期常量**（v0.3 §4.2）：固定字符串字面量等；`enum` 落地前**允许**用固定字符串集（v0.3 §10）。

> 涉及 v0.3 未定义的形态：**裸符号作字段值**（原示例以裸符号充当 `event` 字段值）已移出登记：`plan/hash-v0.3-feature-deltas.md` §2 **D-09**；本文示例一律改用**字符串字面量**——依据 v0.3 §4.2（字段值必须是编译期常量）+ §10（`enum` 落地前**允许**用固定字符串集）。

> 涉及 v0.3 未定义的形态：**运行时分发守卫（`#` 前缀方括号形态 `[k = v]`，形态 2）**、**运行时线程标记（形态 3，`#` + `Thread(...)`）** 已移出登记：`plan/hash-v0.3-feature-deltas.md` §2 **D-06** / **D-07**。

### 2.3 反射查询（EventFuncCollector 模式）——引用 v0.3 §9

> **API 与语义以 v0.3 §9 为准**（§9.1 类型族 / §9.2 内置函数 / §9.3 双态与零成本 / §9.4 运行期消费示例）。本 feature 的 `reflect.collect` 全量 API 已拆到 [[feature-10-reflection-library]]（现行编号：feature-10 **§11.1** 上游契约 / **§11.2** Aura 层类型族）。

```aura
// 标准库 API（不新增语法，普通泛型容器 + reflect 内置模块）
import reflect

fun main(io: Io) throws {
    // collect 返回挂了该注解的全部条目（v0.3 §9.2；推荐消费路径 §9.3 / §9.4）
    for e in reflect.collect("SubscribeEvent") {
        io.println("handler: " + e.name)
        // e.config["event"] / e.config["priority"] —— 取编译期配置值
        // e.invoke(...)                              —— 经物化 CallableObj 调用
    }
}
```

- **口径对齐 v0.3 §9.3 / §9.4**：推荐消费路径 = `reflect.collect("…")` → 逐条 `e.config[...]` / `e.invoke`；条目含 `metadata`（`{ annotator, config }`）与可调用条目的 `invoke`（v0.3 §9.1 / §9.2）。
- `type EventFuncCollector = {}`（用户示例）= 用户侧对 `reflect.collect` 的封装 record，不进语言内核。
- **零成本**：无 `import reflect` 且无注解 ⇒ 产物零变化（v0.3 §9.3）。

### 2.4 注册表与 GC（实现层）

- 注册表与配置值均为 C++ 静态数据（编译期生成），**不涉 GC 堆**；`reflect.collect` 物化的 CallableObj 首次构造后经全局根持有（避免静态构造顺序 + GC 双坑）。

> 涉及 v0.3 未定义的语义：**运行时线程上下文语义**（身份分发 / 上下文设置与匹配 / 上下文传播 / 协程边界，共 6 条）已随运行时族整段移出，登记：`plan/hash-v0.3-feature-deltas.md` §2 **D-08**。

### 2.5 宏形态路线：L2 注解器（与 v0.3 §6.4 对齐）

- **L2 形态** = v0.3 §6.4 的 **`#fun Name(...) -> Code`**（**注解器 / 体替换模型**）：编译期函数返回 `Aura{ ... }` 代码模板，模板内 `#code()` 是原函数体的调用点（调用 0 或 1 次）。其**规范级展开见 [[feature-09-annotator]] §2.2**（体替换模型，用户 2026-09-12 定案）；本特性注册表与配置器值表示即其上游 ABI。
- **核心洞察（实现层）**：宏 = schema（`#type`）+ 处理语义（processor）；本特性的编译期元数据（常量配置值 + 静态注册表 + 符号引用）是注解器与未来宏共享的 **ABI**——处理器无论运行在哪，消费同一份数据表示。故**元数据表示需前瞻兼容**：值域不引入运行时成分。
- **能力边界（诚实声明）**：声明级生成与函数体解构**不在** v0.3 注解器能力内（体替换只做体模板 + `#code` 嵌入，签名恒定、原体不透明；见 [[feature-09-annotator]] §3）；DSL 内嵌（宏内非 Aura 语法）不在路线内（Parser 层正交，元数据路线不做）。

> 涉及 v0.3 未定义的形态：**L1「声明式动作宏 / 动作词汇表」路线**（原三级能力阶梯的 L1 行，含 `#action` 动作子句）已被 [[feature-09-annotator]] §2.2 的注解器体替换模型取代，移出登记：`plan/hash-v0.3-feature-deltas.md` §5 **D-19**。
