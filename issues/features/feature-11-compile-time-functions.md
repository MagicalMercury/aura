# 【编译期函数】[ ] **主标题：`#` 编译期求值体系（值域解释器 → 类型一等值 → Code 注入）——语法规范与安全边界**

> **一句话摘要**：定义 Aura 的编译期函数执行规范——`#` 前缀统一标注编译期语境（`#expr` 求值点 / `#T: type` 编译期参数 / `#code` 代码值），**解释器型求值**（业界共识路线），三期能力分级（值计算 → 类型计算 → AST 注入），同一函数编译期/运行期语义一致为不可破坏红线——本文只定**语法规范、值域边界与分期**，不含实现方案。

## 1. 背景与动机（Why）

- **业务/用户场景**：注解配置值的推导计算（feature-09）、数组长度/容量常量、编译期查表（CRC 表/状态机转移表）、泛型实例化时的类型计算、注解器变量的 Code 生成（feature-09 L1）。
- **当前短板**：无任何编译期求值——常量只能写字面量；泛型只能模板式实例化（无类型级计算）；L2 宏无实现载体。
- **预期收益**：一个 `#` 语法族（与配置器/注解器前缀统一）覆盖三级能力；Phase 2 落地后泛型/反射/代码生成统一为「类型是编译期值」单一模型（Zig 路线验证过的方向）。
- **设计依据**：2026-09-12 业界调研（Zig comptime / Rust const 三层 / Jai #run / D CTFE / Nim 分层 / C++ constexpr 演进 / Carbon）——核心结论：**解释器型**是主流共识（沙箱可控、按目标平台语义求值）；编译运行型（Circle/Jai 全开）语义漂移与构建不可复现代价已被业界认知，不采纳。

## 2. 语法规范（What）

### 2.1 统一原则：`#` = 编译期语境标记

`#` 前缀在整个语言中语义唯一：**「随后的东西在编译期处理」**——配置器（#type/#X/#[...]，feature-08/09）与本体系的 `#expr` / `#T: type` / `#code` 同族。

### 2.2 Phase 1：编译期值求值（`#expr` + 函数双用）

```aura
// 编译期求值点：#( 表达式 )——任何允许常量的位置
let N: int = #(fib(10))                    // 函数调用编译期执行，结果织入为立即数
let buf = [0; #(N * 2)]                    // 数组长度
let TAG: str = #(build_tag("v1", 3))       // 字符串计算

// 函数无需任何标记即可双用（D/Zig 模型）：普通调用 = 运行期，#() 内 = 编译期
fun fib(n: int) -> int {
    if n <= 1 { return n }
    return fib(n - 1) + fib(n - 2)
}

// 编译期块（多语句计算，返回最后表达式值）
let M = #{
    let a = fib(8)
    let b = a * 2
    b + 1
}
```

- **隐式触发**：数组长度、注解配置值（feature-09）、`#[k=v]` 值侧（feature-08）等**常量语境**自动进入编译期求值（无需显式 #()）。
- **编译期函数定义形态**（可选强化，consteval 对位）：

```aura
#fun crc_table() -> Array<int> { ... }     // #fun = 仅限编译期调用的函数（运行期调用 = 编译错误）
fun fib(n: int) -> int { ... }              // 无标记 = 双用（调用点决定）
```

### 2.3 Phase 2：类型作为编译期一等值（`#T: type`）

```aura
// 编译期类型参数：type 关键字类型
fun zeroed(#T: type) -> T {
    return default(T)                        // default/size_of/type_name 等编译期内建
}

let a = zeroed(int)                          // 类型作实参（编译期值）
let b = zeroed(Player)

// 类型内建（编译期函数，配合 reflect——feature-10 §2.2c）
#type_name(T)                                // -> str（编译期）
#size_of(T)                                  // -> int
#reflect.type(#Player)                       // -> 编译期 TypeInfo

// 泛型统一通道（演进方向，规范预留）：现有泛型语法不变，
// # 参数是新的增量通道——接收编译期值的函数（类型/常量混合）
fun make_pair(#A: type, #B: type, a: A, b: B) -> Pair<A, B> { ... }
```

- **语义**：`type` 只能出现在 `#` 参数位/编译期语境——运行期值域不含类型（无运行时类型对象泄漏；TypeInfo 由 reflect 库承载运行时形态）。

### 2.4 Phase 3：Code 值与注入（服务 feature-09 L1 注解器变量）

```aura
// #code：编译期代码值（AST 片段，词法捕获、目标作用域解析——卫生性规则）
let c: Code = #code { io.println("hi") }

// 注入：Code 值在声明/语句位置展开（仅处理器宏等编译期语境可注入）
fun demo() {
    #insert c                                // 展开为真实语句
}

// 注解器变量通道（feature-09 L1 完整形态）
#processor = fun(cfg, target) -> Code { ... }   // 返回 Code → 织入目标声明
```

- **Code 值域**：恒为**合法 Aura AST**（`#code { ... }` 解析期即校验语法）；不可序列化为字符串再拼接（**不做 D mixin**——文本拼码错误质量差是业界教训）。

### 2.5 求值安全边界（三级共用，红线级规范）

| 禁止项 | 规则 |
| :--- | :--- |
| IO（文件/网络/控制台） | 编译期求值上下文一律禁止——**不做 Jai 式全开**（构建不可复现） |
| 时钟 / 随机 / 环境变量 | 禁止（编译期求值必须确定性、可复现） |
| 堆分配 | 允许求值期临时分配，**必须在求值结束前释放**（transient allocation，Rust/C++ 模型）；逃逸出求值结果 = 编译错误 |
| 全局/静态可变状态 | 禁止读写 |
| 协程（spawn/co_await/channel） | 禁止（无运行时） |
| 外部函数（FFI/stdlib IO 面） | 禁止——可调用集 = 纯函数 + 编译期内建（白名单） |

- **语义一致性红线**：同一函数编译期与运行期执行**结果必须一致**（解释器按 Aura 目标语义求值，非宿主 C++ 语义——交叉编译正确性，Rust「按目标平台解释」教训）；违例（如浮点环境差异）在规范层禁用（编译期浮点 = 精确 IEEE 语义）。
- **求值失败**：未定义行为（除零/越界/None unwrap）= 编译错误（报求值栈，指向源位置）。
- **求值时限**：编译器可配置求值步数上限（防 `#(while(true){})`）——超限 = 编译错误。

## 3. 与既有体系的衔接（规范级）

- **泛型**：现有模板式泛型**语法与行为不变**（存量零破坏）；`#` 参数是并行的增量通道，Phase 2 后新代码可选用——两者可混用（`fun f<T>(x: T, #N: int)`）。
- **注解器**：feature-09 的配置器值域 = Phase 1 值域子集（Phase 1 落地后，注解值自动获得 `#()` 计算能力）。
- **运行时守卫**（feature-08）：`#[k = v]` 的 v 侧 = 编译期常量语境（隐式触发）。
- **配置器语法共享**：`#` 后跟 `type`/标识符`{`/`[`/`(`/`fun` 等的文法歧义由 Parser 上下文消解（规范附文法表，实现期定稿）。

## 4. 依赖与前置条件（Dependencies）

- **无上游依赖**（自是基建）；Phase 2 的 `#reflect.type` 依赖 [[feature-10-reflection-library]] Phase R2 元数据；Phase 1+3 被 [[feature-09-annotator]] L1 注解器变量消费（统一 decorator 模型，2026-09-12 定案）。
- **求值器形态决策（已定）**：解释器型（AST 树遍历起步，性能瓶颈后可演进字节码——Clang 先例，10 倍空间）——**不做**编译运行型（宿主语义漂移 + 任意代码执行风险）。
- **外部依赖**：无。
