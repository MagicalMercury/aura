# 【编译期函数】[ ] **主标题：`#` 编译期求值体系（值域解释器 → 类型一等值 → Code 注入）——语法规范与安全边界**

> **一句话摘要**：Aura 编译期求值体系的**语法对齐 + 安全边界 + 能力分期**。**语法一律以 v0.3 为准**（`plan/hash-metadata-requirements.md`，本文只引用、不重复定义）：`#` 的五档角色与精确语义（§1.1–§1.3）、形态骨架与形态判定（§3.1）、`#fun` 与调用规范（§6.1/§6.2）、`#(expr)`/`#{...}` 求值（§7.1–§7.3）、值注入三×三表（§7.4）、`#c` 展开语义（§7.6）、`Code` 三位置（§6.4）、reflect 双态（§9.3）。本文正文**只保留 v0.3 已定义的形态**；与 v0.3 有差异 / v0.3 未定义的形态已移出，集中登记于 `plan/hash-v0.3-feature-deltas.md`（D-01…D-06）。本文保留**实现层内容**：解释器型求值路线（业界共识）、三期能力分级（值计算 → 类型计算 → AST 注入）、值域边界与「同一函数编译期/运行期语义一致」红线，不含实现方案。

## 1. 背景与动机（Why）

- **业务/用户场景**：注解配置值的推导计算（feature-09）、数组长度/容量常量、编译期查表（CRC 表/状态机转移表）、泛型实例化时的类型计算、注解器变量的 Code 生成（feature-09 L1）。
- **当前短板**：无任何编译期求值——常量只能写字面量；泛型只能模板式实例化（无类型级计算）；L2 宏无实现载体。
- **预期收益**：一个 `#` 语法族（与既有 `#` 指令前缀统一）覆盖三级能力；Phase 2 落地后泛型/反射/代码生成统一为「类型是编译期值」单一模型（Zig 路线验证过的方向）。
- **设计依据**：2026-09-12 业界调研（Zig comptime / Rust const 三层 / Jai #run / D CTFE / Nim 分层 / C++ constexpr 演进 / Carbon）——核心结论：**解释器型**是主流共识（沙箱可控、按目标平台语义求值）；编译运行型（Circle/Jai 全开）语义漂移与构建不可复现代价已被业界认知，不采纳。

## 2. 语法规范（What）—— 一律引用 v0.3

> 本节语法定义以 **v0.3**（`plan/hash-metadata-requirements.md`）为准：只做**引用与落位**，不另立说法、不重复定义。凡本节涉及、但 v0.3 未定义的形态，均**移出正文**并改为指向 `plan/hash-v0.3-feature-deltas.md` 的引用行。

### 2.1 `#` 的统一直觉与五档角色（v0.3 §1.1–§1.3）

- `#` 的所有用法共享一个直觉：**「编译期」**（§1.1）；但 `#` 在不同位置承担不同角色，不是同一条规则。
- **五档角色**（§1.2）：**定义标记**（`#fun` / `#type`）· **类型引用**（`#名字`，指向 `#type`）· **调用标记**（`#名字(...)`）· **值引用 / 注入**（`#名字`，指向 `#const`，即 `#c`）· **求值标记**（`#(expr)` / `#{...}`）。
- **精确语义**（§1.3）：`#` 标记的是「**默认不在编译期发生的事**」——即需要**显式翻转**到编译期的地方。
- **不必写 `#`**（§1.3 / §6.2 规则 4）：字面量、算术、编译期内建、**编译期值的字段/索引访问**（`CFG.priority`、`BIT[3]`）——这些默认就在编译期，无运行期歧义。
- **元数据 vs 编译期值**（§1.4）：元数据是**被挂载到声明上的**编译期值，是编译期值的一个子集；「挂载」是元数据的定义性特征。

### 2.2 形态骨架与形态判定（v0.3 §3.1 / §3.2）

- `#` 之后写什么决定**形态骨架**（§3.1）：`type` / `fun` / 标识符`.`（既有编译器指令，§1.5 暂不处理）/ 标识符（裸，值引用 `#c`）/ 标识符`{` / 标识符`(` / `(` / `{`；文法歧义由 Parser 上下文消解。
- **形态判定推迟到展开之后**（规则甲，§3.1 / §7.6.4–§7.6.5）：「一个 token 前看」**只适用于未展开的形态骨架**，不承诺最终形态——因为 `#c` 展开后可能成为 `#X{...}` / `#X(...)`。
- `where` 是**软关键字**（§3.2）：只在 `}` 之后或参数表 `)` 之后按关键字解析；其它位置仍是普通标识符。

### 2.3 Phase 1：编译期值求值（v0.3 §6.1/§6.2/§7.1–§7.3/§7.5/§8.2）

```aura
// ① 编译期调用：调用点必须写 `#`（v0.3 §6.2 规则 1）；`#` 作用于整个调用表达式（规则 2）
#const BIT = #bit_table()                     // 调 `#fun`

// ② 单表达式求值：`#(expr)`（v0.3 §7.1）
#const PRI = #(3 * 2 + 1)                     // → 7

// ③ 多语句块：必须显式 `return`，值 = `return` 的值（v0.3 §7.2）
#const SPAN = #{
    let n = #bit_table().len()
    return n * 4
}

// ④ `let` 绑定：运行期变量，编译期初值（v0.3 §7.5 例④）
let M: int = #fib(10)                         // 普通纯函数：`#` + 调用 = 要求编译期求值（§6.2 规则 5）

// ⑤ `fun` 双用（D/Zig 模型）：定义无需标记，调用点决定求值时机
fun fib(n: int) -> int {
    if n <= 1 { return n }
    return fib(n - 1) + fib(n - 2)
}
```

- **`#(expr)` ≡ `#{ return expr }`**：`#(expr)` 是语法糖，也是唯一可省 `return` 的例外；`#{}` **必须显式 `return`**（§7.1–§7.3）。
- **调用点必须写 `#`**：`#const BIT = #bit_table()`；漏写成 `bit_table()` ⇒ **编译错误**（§6.2 规则 1）。`#` **作用于整个调用表达式**（含实参，§6.2 规则 2）。
- **`#fun`**：只在编译期存在、只在编译期执行；与 `fun` 的差别**只有两条**（§6.1）。运行期调用（漏 `#`）⇒ **编译错误**（§6.2 规则 1）；`#fun` 只能被 `#名字(...)` 调用（§6.2 规则 5）。

```aura
#fun crc_table() -> [int] { ... }             // `#fun` = 仅限编译期调用（运行期调用 ⇒ 编译错误）
```

- **编译期语境（隐式触发）**：`#const` 初值、数组长度、注解字段实参、类型位置、`where` 的 `by #fun` 谓词体等「值必须已知」的位置（§8.2）**不需要额外的 `#()` 包裹**，但其中出现的**编译期调用仍必须写 `#`**（§8.2）。
- **值注入位置语义**：`#{}` / `#c` 的值「就地铺开」，结果由**值类型 + 所在位置**共同决定（三×三表，§7.4；详见 §2.7）。
- **`#const` 绑定 AST 片段**（§8.1）：`#const x = expr` 绑定的是 `expr` 的 **AST 片段**（未求值），`#const x = #(expr)` 才绑定求值后的值——要绑定值就显式求值。

### 2.4 Phase 2：编译期类型计算（v0.3 §1.2/§4/§5.5/§9.3）

```aura
// 编译期类型是一等值：`#type` 定义 + `#名字` 引用（v0.3 §1.2 类型引用 / §4.1 / §4.6）
#type EventRegister = {
    event: string,
    priority: int = 0,
}
#const CFG: #EventRegister = #EventRegister{ event = "Tick" }   // 编译期值（未挂载 ⇒ 不是元数据，§1.4）
#const PRI = CFG.priority                      // 编译期值字段访问：不必写 `#`（§6.2 规则 4）

// 编译期内建（v0.3 §6.2 规则 4 点名 `#size_of(T)`）
#const SZ = #size_of(int)                      // -> int

// 编译期 reflect（v0.3 §9.3 双态：`#reflect.*` 与运行期 `reflect.*` 同名同义）
#reflect.type(#EventRegister)                  // -> 编译期类型视图
#reflect.type_equal(#EventRegister, #EventRegister)  // -> bool

// `#type` 的方法只在编译期显式调用、不自动触发（v0.3 §4.5）
#type Command = { name: string }
fun (self #Command) describe() -> string { ... }
#const DESC = #Command{ name = "/x" }.describe()

// 泛型侧（v0.3 §5.5）：现有「参数位引入」写法不变，调用方不写尖括号
fun max(a: <T>, b: <T>) -> T where { T: Comparable } { ... }
```

- **类型作为编译期值**：`#type` 定义编译期类型（§4.1，不进运行期类型系统、不分配 GC）；`#名字` 是「类型引用」形态（§1.2 五档之一）；`#const` / 字段访问在编译期完成（§4.6）。
- **编译期类型的边界**（§4.7）：可出现在 `#X{...}` 构造、`#X` 类型标注、`fun (self #X)`、`where` 引用、`#fun` 参数/返回类型；**禁止**运行期变量持有、运行期参数/返回、放进运行期容器。
- **运行期类型视图**由 `reflect` 库承载（§9）；编译期由 `#reflect.*` 提供（§9.3），二者**同名同义**。

> 涉及 v0.3 未定义的形态：**编译期类型参数（`#` 参数位）**、**`#type_name` / `default` 编译期内建**，已移出登记：`plan/hash-v0.3-feature-deltas.md` §1 D-01 / D-04。

### 2.5 Phase 3：`Code` 值与 `#c` 注入（v0.3 §6.4/§7.4–§7.6）

```aura
// Code 型编译期函数 = 注解器；体内用 `Aura{ ... }` 写真实 Aura 代码（v0.3 §6.4）
#fun Logged(tag: string, level: string = "INFO") -> Code {
    return Aura {
        log_enter(tag, level)
        let r = #code()
        log_exit(tag, level)
        return r
    }
}
#Logged(tag = "db")
fun query(sql: string) -> Row { return db.exec(sql) }

// 语句位置注入：先把 Code 绑成 `#const`，再按名以 `#c` 注入（v0.3 §7.5 例⑦）
#const inj: Code = #{
    return Aura {
        let n = 3 + 4
        return n
    }
}
fun demo() {
    #c                                        // 展开为真实语句序列（§7.6.3）
    io.println("after")
}
```

- **`Code` 值的三个合法位置**（§6.4）：① **挂载应用**（§4.3）；② **语句位置注入**（`#c`，§7.6.3）；③ **`#const` 绑定**（绑定后经 `#c` 再注入）。**禁止**在**表达式位置**出现（§7.6.3 规则 4）。v0.2 时代的独立注入关键字已被 v0.3 §6.4 删除——与 `#c` 是同一语义，全文统一写 `#c`。
- **`#code()`** 调用 0 次（跳过原体）或 1 次（§6.4）；`return` 规则（体替换模型）：**绑定后置返回**（`let res = #code()` → 后处理 → 末尾 `return res`）或**直返**（`return #code()`，§6.4）。
- **多个 `Code` 型 `#fun` 叠加**：**近声明者先应用**（内层产物成为外层的 `#code`，§4.3 / §6.4）；同一声明挂同一配置器两次 ⇒ **编译错误**（§4.3）。
- **挂载后果由实体类型决定**（§4.4）：`#type` 构造 ⇒ 只登记元数据；`#fun` 返回 `Code` ⇒ 编译期执行并织入。**挂载点的 `#fun` 必须返回 `Code`**，非 `Code` ⇒ **编译错误**（§4.4）。
- **`Code` 值域**恒为**合法 Aura AST**（`Aura{ ... }` 里写真实代码；解析期即校验语法）；**不做**字符串拼码（文本拼码错误质量差是业界教训）。
- **不递归**（§4.3）：织入产物中新出现的 `#` 只登记元数据，**不再**触发织入。

> 涉及 v0.3 未定义的形态：**带体块的 `Code` 构造（`#code{ ... }`）**、**注解器变量的命名式写法**，已移出登记：`plan/hash-v0.3-feature-deltas.md` §1 D-02 / D-03。

### 2.6 求值安全边界与一致性红线（v0.3 §6.3）

> 边界以 v0.3 §6.3 为准（能算什么 / 不能算什么 / 上限 / 错误语义）；本文补充实现层红线。

- **能算**：`int`/`float`/`bool`/`string`/`None` · 数组 / record 构造与字段读 / `Optional` / union · 算术 / 比较 / 逻辑 / 字符串拼接与切片 / 索引与长度 · `if`/`while`/`for`/提前 `return` · 调用其它 `#fun`、编译期内建、**纯函数** · 局部变量 / `#const` / 递归（§6.3）。
- **不能算（禁止）**：IO · 并发 · 时钟 / 随机 / 环境变量 · 全局可变状态 · C++ 桥接函数 · **堆对象逃逸**（§6.3）。
- **临时分配**：允许求值期临时分配，**必须在求值结束前释放**（transient allocation，Rust/C++ 模型）；逃逸出求值结果 = 编译错误。
- **上限**：步数上限 + 内存上限；超限 ⇒ **编译错误**（§6.3）。
- **错误语义**：求值失败 = **编译错误**，附**求值栈 + 源位置**；**禁止**静默、**禁止**回退为运行期求值（§6.3）；主动报错用 `#compile_error("信息")`。
- **语义一致性红线**（本文实现层）：同一函数编译期与运行期执行**结果必须一致**（解释器按 Aura **目标语义**求值，非宿主 C++ 语义——交叉编译正确性，Rust「按目标平台解释」教训）；违例（如浮点环境差异）在规范层禁用（编译期浮点 = 精确 IEEE 语义）。
- **未定义行为**：除零 / 越界 / `None` unwrap = **编译错误**（报求值栈，指向源位置）。
- **求值时限**：编译器可配置求值步数上限（防 `#{ while(true) {} }`）——超限 = 编译错误。

### 2.7 `#c` 的展开语义（v0.3 §7.6）

- **绑定模型**：`#const c = expr` 绑定的是 **`expr` 的 AST 片段**，不是求值后的值；`#(expr)` 才是「求值后铺开」（§7.6.1 / §8.1）。`#const` 因此「**像宏**」——是具名 AST 片段，不是值绑定。
- **展开规则**（§7.6.2）：**先收集全部 `#const` 并按定义顺序排列；按顺序每个 `#const` 对整段代码各做一遍替换，每遍不回头**。
  - **定义顺序影响结果**：`A→B→A` 与 `B→A→B` 两种定义顺序得到不同的最终形态。
  - **无括号插入**（照搬 C 规则）：`#const A = #N * 2` 展开为 `3 + 4 * 2`（不是 `(3+4)*2`）；需要整体优先由用户自己加括号（`(#N) * 2`）。
  - **终止性**：每个 `#const` 只替换一遍 ⇒ 多遍扫描**必然终止**；即使循环定义也只停在最后一次替换后的状态（不报错）。
- **位置语义（三×三表）**（§7.4 / §7.6.3；表引自 v0.3，以 v0.3 为准）：

| `#c` / `#{}` | 表达式位置 | 语句位置 | 声明前 |
| :--- | :--- | :--- | :--- |
| `c` 是 `Code` | ❌ 编译错误（规则 4） | ✅ **注入**（铺开成语句序列） | ✅ **挂载**（Code 应用到紧跟的声明） |
| `c` 是元数据（`#type` 实例） | ✅ 值 | ❌ 编译错误（不是语句） | ✅ **挂载**（登记元数据） |
| `c` 是普通值（`int`/`string`/…） | ✅ 值 | ❌ 编译错误（不是语句） | ❌ 编译错误（不是元数据） |

- **形态判定推迟到展开之后**（规则甲，§3.1 / §7.6.4–§7.6.5）：`#c` 展开后可能成为 `#X{...}` / `#X(...)`，因此编译前端只识别「**形态骨架**」，最终形态（含挂载判定）在展开完成后确定。

## 3. 与既有体系的衔接（v0.3 §3.1/§5.5/§10）

- **泛型**：现有泛型**语法与行为不变**（存量零破坏）；参数位引入的现行写法以 v0.3 §5.5 为准（`fun max(a: <T>, b: <T>) -> T`，调用方不写尖括号）；`where` **只约束、不引入**（§5.5）。`#` 一族**不引入新的泛型写法**——「类型作为编译期值」经 `#type` / `#名字` / `#const` 表达（§4.6）。
- **注解器**：feature-09 的配置器值域 = Phase 1 值域子集；Phase 1 落地后，注解字段实参（v0.3 §8.2 编译期语境）可用编译期计算（其中的调用**仍须写 `#`**）。
- **反射读取路径**：运行期读元数据走 `reflect.collect(...)`（§9.2/§9.3）；编译期读走 `#reflect.*`（§9.3）——双态同名同义。
- **模块级常量**：用 `#const`（§8.3，当前语言禁止模块级 `const`）。
- **`#` 指令共存**：`#` + 标识符 + `.` 仍是指令；其余形态按 §3.1 消解（形态判定推迟到展开后，见 §2.2）。
