## 1. 01-introduction.md — 简介

### 1.1 行 5：「全静态类型，函数类型必须显式标注」

**问题**：表述存在歧义。"函数类型必须显式标注"容易被误解为"所有函数类型的变量都必须显式标注类型"，而根据 `05-functions.md` §5.1 的规则，实际含义是**顶层函数和方法的参数类型与返回类型必须显式标注**。闭包赋值给变量时，变量类型是可以推断的（`let add = fun(a: int, b: int) -> int { ... }` 中的 `add` 未标注类型）。

**建议修改**：

> 全静态类型：顶层函数和方法的参数与返回值必须显式标注；变量类型通常可推断。

### 1.2 行 10：「支持一等函数（闭包），函数类型和值使用统一的关键字 `fun`」

**问题**：表述略显拗口。"函数类型和值使用统一的关键字 `fun`"不够直观，读者可能不明白"类型和值都用 `fun`"是什么意思。

**建议修改**：

> 支持一等函数与闭包：函数类型和函数值均使用 `fun` 关键字统一表达（如 `fun(int, int) -> int` 既是类型也是值的构造形式）。

## 3. 03-types.md — 类型系统（⚠️ 问题最多）

### 3.1 🔴 行 133：未定义的 `Pair` 类型和 `zip` 函数

```aura
let pair: Pair<string, int> = zip("age", 30)
```

**问题**：`Pair` 类型别名在前文（行 114-119）的 `type` 示例中**并未定义**。该处只定义了 `User`、`Stack<T>`、`MaybeFloat`、`Action` 四个别名。`zip` 函数也未在任何位置声明或定义。读者会在这一行卡住："Pair 是什么？zip 从哪来的？"

这是一个**事实性错误**——示例引用了不存在的类型和函数。

**建议修改**：

- 方案 A：在行 118（`type Action = ...`）之后增加 `type Pair<A, B> = { first: A, second: B }` 的定义，并将 `zip` 替换为一个已定义的简单示例或用注释说明 `zip` 为假设的外部函数。
- 方案 B：直接删除该行，或改为使用已定义的类型，如：

```aura
let s: Stack<int> = Stack()
// 更多实例化示例：
let items: Stack<string> = Stack()
```

### 3.2 🟡 记录创建语法分散引入，缺乏统一说明

文件在三个位置以不同语法创建记录，但从未给出统一对照：

| 位置 | 语法 | 示例 |
|------|------|------|
| §3.2 行 38 | 匿名 record 按字段名 | `{ x = 3, y = 4 }` |
| §3.2 行 39 | 匿名 record 按顺序 | `{ 3, 4 }` |
| §3.3 行 125 | 命名类型构造函数（圆括号，按顺序） | `User(1, "Alice")` |
| §4 行 17（04-variables.md） | 命名类型构造函数（花括号，按字段名） | `Point{x=1, y=2}` |

读者需要自己归纳出四种语法的关系。尤其是：
- 圆括号 `User(1, "Alice")` 和花括号 `Point{x=1, y=2}` 的区别是什么？是两种等价写法还是语义不同？
- 何时用 `Type(...)`、何时用 `Type{...}`、何时直接用 `{...}`？

**建议修改**：

在 §3.2 末尾或 §3.3 开头增加一个**记录创建语法速查**小节：

```markdown
### 记录创建语法速查

| 语法 | 含义 | 示例 |
|------|------|------|
| `{ field = val, ... }` | 匿名 record，按字段名 | `{ x = 3, y = 4 }` |
| `{ val1, val2, ... }` | 匿名 record，按字段顺序 | `{ 3, 4 }` |
| `TypeName(val1, val2, ...)` | 命名类型构造，按字段顺序 | `User(1, "Alice")` |
| `TypeName{field = val, ...}` | 命名类型构造，按字段名 | `Point{x=1, y=2}` |
```

### 3.3 🟡 行 132：`Stack()` 零参数构造语义不明

```aura
let s: Stack<int> = Stack()
```

`Stack<T>` 定义为 `{ items: [T], top: int }`，有两个字段，但这里用零参数调用 `Stack()`。字段的初始值是什么？`items = []`、`top = 0`？还是未初始化？

**建议**：在示例旁加注释说明零参数构造的语义（零值初始化 / 默认值），或在文档前面的"零值"概念处统一说明。

### 3.4 🟢 行 125 注释：「User 替代 { id: int, name: string }」

注释本身没问题，但由于紧接着的代码是 `User(1, "Alice")` 而非 `{ id = 1, name = "Alice" }`，读者可能困惑：`User(...)` 是否等价于 `{ id = ..., name = ... }`？如果是，等价规则是什么？

**建议**：注释改为：

```aura
let user: User = User(1, "Alice")   // 等价于 { id = 1, name = "Alice" }，按字段顺序传参
```

### 3.5 🟢 行 7：`None` 类型说明位置偏早

"`None` 不能作为变量的声明类型（联合类型除外）"放在 §3.1「基础类型」中稍显突兀——读者尚未接触联合类型（§3.2 才引入），却已被要求理解"联合类型除外"这一例外。

**建议**：将 `None` 的详细约束（不能单独作为变量类型，可与联合类型配合）移到 §3.1 `None` 介绍后紧跟一句 \<!-- 详见 §3.2 联合类型 --> 的引导，或在 §3.2 联合类型处回头说明。

## 5. 05-functions.md — 函数

### 5.1 🟡 行 60：闭包参数类型推断——有声明无示例
