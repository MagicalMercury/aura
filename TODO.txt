字符串拼接性能优化 issue  [2026-07-29 提出]
----------------------------------------------------------------
背景：1000 万次 `s = s + "a"` 循环奇慢。调研定位 4 个独立瓶颈：
  - 瓶颈 1 (≈60%)：GcRootHandle 全局 mutex，每次拼接 6~8 个 handle → 1.4 亿次 mutex 操作
  - 瓶颈 2 (≈15%)：intern_string 无 thread_local 缓存，每次字面量都走全局锁
  - 瓶颈 3 (≈10%)：GC 阈值过小（256KB/1MB），频繁 STW
  - 瓶颈 4 (≈15%)：Rope 左倾退化藤蔓，Fibonacci 边界每 ~20-30 次强制 flatten，O(n²)
关联 issue 调研：plan/J_Test_Performance_Optimization.md（瓶颈分析）
       plan/gcstring_optimization.md §七 D1（intern 池已实施）

[ ] P3  全部内置函数调用改用 GcRootHandle 类型  [2026-07-29 提出，远期计划]
      - 背景：当前内置函数（io.println / string.append / array.append 等）的 GC 对象参数
        多以裸 GcObject* / GcString* 传递，函数内部需手动构造 GcRootHandle 保护，
        导致：
          * 每次调用重复构造/析构 GcRootHandle（mutex 开销，与优化 1 关联）
          * 函数签名不统一（部分裸指针、部分 GcRootHandle）
          * 调用方与被调用方职责不清（谁负责 root？）
      - 目标：将所有内置函数的 GC 对象参数统一改为 GcRootHandle<T> 类型
          * 调用方传入 GcRootHandle（已 root，函数内无需重复构造）
          * 函数签名统一：fn(GcRootHandle<GcString*> s, ...) 而非 fn(GcString* s, ...)
          * CodeGen 生成调用时自动传递 GcRootHandle（而非裸指针）
      - 范围：
          * runtime/builtin/io.h/cpp（io.println / io.read_file 等）
          * runtime/builtin/string.h/cpp（concat / append / slice / intern_string 等）
          * runtime/builtin/array.h（Array::append / insert / pop 等）
          * runtime/builtin/mutex.h/cpp（Mutex / RWMutex / Once 方法）
          * src/Sema/BuiltinRegistry.h（函数签名表更新）
          * src/CodeGen/ExprGen.cpp（生成 GcRootHandle 传递而非裸指针）
      - 前置依赖：
          * ✅ 优化 1（GcRootHandle 线程局部链表）已完成（2026-08-22 核账确认：
            handles.h ValueThreadLocal 模式走 registerRootThreadLocal 线程局部
            链表，仅 ValueGlobal 走全局容器；根注册无全局 mutex）——本条目
            触发条件"优化 1 实施完成"已满足
          * GcRootHandle::rebind 语义明确（append 返回值赋回场景）
      - 优点：
          * 职责清晰：调用方负责 root，被调用方直接使用
          * 消除函数内重复 GcRootHandle 构造（与优化 1 协同，收益最大化）
          * 签名统一，类型安全（编译期保证 GC 对象被 root）
          * 为未来精确栈扫描铺路（所有 GC 对象引用都通过 GcRootHandle 可追溯）
      - 代价/风险：
          * 工程量巨大：涉及所有内置函数签名变更 + CodeGen 改造
          * 破坏性变更：所有内置函数 ABI 变更，需全量测试
          * 非 GC 对象参数（int/float/bool）不受影响，需区分处理
          * 性能风险：若优化 1 未先实施，反而变慢（每次调用都 mutex）
      - 关联：
          * 优化 1（GcRootHandle 线程局部链表）：本项的前置依赖
          * 优化 2（intern_string 线程局部缓存）：intern_string 签名变更需协同
          * plan/gcstring_optimization.md（GcString 优化历史）
          * plan/done/codegen_gc_safety_audit.md（CodeGen GC 安全审计）
      - 触发条件（满足任一即可启动）：
          * 优化 1 实施完成，GcRootHandle 构造零开销
          * 出现因裸指针传递导致的 GC 安全 bug（如 compact 期间悬垂）
