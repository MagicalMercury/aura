[x] P1  sync thread 多线程语句  [2026-07-24 完成]
      - plan：plan/sync_thread_plan.md（详细实施方案已就绪）
      - 实现：
          * 进程级全局线程池 + FIFO 全局队列（方案 A，见 issue 决策）
          * 无界 sync thread 默认上限 = hardware_concurrency
          * safepoint 三层插入：L1 分配点（已有）/ L2 循环回边 / L3 任务边界
          * 工作线程启动时 registerThread，退出时 unregisterThread
          * spawn 内强制 ioSync_ = true（必须用 _sync 版本）
          * TLAB（Thread-Local Allocation Buffer）每线程独立分配缓冲，避免多线程竞争全局分配
      - 配套修复：
          * GC 并发数据竞争：compactSuspendedCount_/gcPending_/oomInit_ 改 atomic
          * roots_ (unordered_set) 并发 UAF → 新增 rootsM_ 互斥锁
          * rememberedSet_ 并发 → 新增 rememberedSetM_ 互斥锁
          * intern_string 持锁 alloc 导致 STW 死锁 → 改为"不持锁 alloc"模式
          * cout 无锁并发 → 新增 g_coutM 互斥锁保护 println/println_sync
          * 线程池 ensureStarted 无锁初始化 → 用 std::call_once 保护
          * MinGW std::shared_mutex bug → 改用 std::mutex（msys2/MINGW-packages#25193）
          * worker 空闲时不响应 GC → cv_.wait_for 超时定期检查 gcPending_
      - 验证：test.aura 全部 3 个测试通过，退出码 0
        - 测试 1：基本多线程（无界）2 行 "hello from thread N"
        - 测试 2：有界并发 max=4，10 行 "task N"
        - 测试 3：GC 压力 max=2，100 行 "string N" + done
        - 输出顺序有少量交错（多线程并发正常现象），无数据损坏
      - 前置工作：循环回边 safepoint 插入（StmtGen 改动，单线程也受益）
      - 文件：src/AST/Stmt.h, src/Parser/StmtParser.cpp,

          lock (rw.r()) { ... }     # RWMutex 读（v1.1 ✅）
          lock (rw.w()) { ... }     # RWMutex 写（v1.1 ✅）
          lock (once) { ... }       # Once 一次性执行（v1.1 ✅）

      - 关键设计（v1.0 死锁修复确立）：
          * 间接指针持有同步原语（std::timed_mutex 不可移动，规避 compact memcpy 损坏）
          * 终结器释放间接原语（复用现有 GC finalizer 机制）
          * timed_mutex + try_lock 轮询 + gc_safepoint()（避免 STW 死锁）
          * RWMutex 用 timed_mutex + atomic 计数模拟（规避 MinGW shared_mutex bug）
          * Guard 持有 GcRootHandle + locked_ 标志（防 compact 悬垂 + 防 TSan 误报）
      - v1.2 新增设计：
          * 多锁语句：全 Mutex 场景按指针地址排序后逐个获取（等价 std::scoped_lock
            死锁避免效果，但保留 safepoint 轮询感知）；混合场景（含 RWMutex.r()/.w()）
            按声明顺序获取，用户需自行保证锁序一致
          * RWMutex 批量唤醒 reader：generation 代际计数器 + 8 次 yield 短自旋，
            writer 释放时 ++generation 唤醒所有等待 reader，减少逐个 notify 开销
          * L5 递归持锁检测：Mutex.owner / RWMutex.writer_owner 记录线程 ID，
            检测到递归持锁抛 Aura Error{RuntimeError, "recursive lock detected"}（非 abort）
          * 协程 try/catch 无 setupLet 时用 IIFE + std::variant<monostate, Error>
            模式，规避 C++ 标准禁止 catch handler 内 co_await 的限制
          * Once::do_ 用 GcRootHandle<Once*> selfRoot 保护 this，防 compact GC 移动后悬垂
