## ✅ 已解决：shared_mutex 断言 __ret == 0
根因：MinGW 下 std::shared_mutex 实现有 bug
  - 参考：https://github.com/msys2/MINGW-packages/issues/25193
  - 现象：lock_shared() 抛 "__ret == 0" 断言，多线程测试第一行即崩溃
修复：runtime/builtin/string.cpp:527-561
  - 将 g_internMutex 类型从 std::shared_mutex 改为 std::mutex
  - intern_string 读路径由 std::shared_lock 改为 std::lock_guard（独占锁）
  - unordered_map::find() 耗时极小，独占锁对并发性能影响可忽略
  - 移除 #include <shared_mutex>，改为 #include <mutex>
验证：test.aura 全部 3 个测试通过，退出码 0
  - 测试 1：2 行 "hello from thread N"
  - 测试 2：10 行 "task N"（0-9）
  - 测试 3：100 行 "string N"（0-99）
  - 最后输出 "done"
  - 输出顺序有少量交错（如 string 5 在 string 4 前），属多线程并发正常现象
