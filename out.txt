**阻塞性问题详述**：

经 5 个 Agent 联合检索确认（test.aura 全文 / BuiltinRegistry.h L335-337 / ExprGen.cpp L641-644 / ExprInfer.cpp L196-203 / src/ 全目录 Grep），Aura 语言中**不存在 `optional(...)` 函数**。构造 `Optional<T>` 值的正确方式有三种：

1. **`some(value)`** —— 显式构造 Some 值（BuiltinRegistry.h L335 注册，ExprGen.cpp L641-644 生成 `make_optional(...)`）
2. **`none()`** —— 构造 None 值（test.aura 已大量使用）
3. **隐式装箱** —— `let x: Optional<T> = value`（DeclGen.cpp L337-359 P3a 折叠，生成 `make_optional<T>(value)`，类型由左侧注解驱动）

**⚠️ 关于 `some("abc")` 的字符串 CTAD 陷阱**：ExprGen.cpp L643 生成 `aura_rt::make_optional("abc")` 依赖 C++ CTAD，字符串字面量 `"abc"` 退化为 `const char*`，推导出 `Optional<const char*>*`，与目标 `Optional<GcString*>*` 类型不匹配，**m10/u6 若用 `some("abc")`/`some(u6t)` 可能编译失败**。

**推荐修复方案**：m10/m11/u6 改用**隐式装箱**（方案 B，类型安全）：
```
let m10o: Optional<string> = "abc"
let u6o: Optional<string> = u6t
let m11o: Optional<int> = 7
```
DeclGen.cpp L337-359 会从左侧 `OptionalSemType::elementType` 映射 `elemCpp`，生成 `make_optional<GcString*>("abc")` 和 `make_optional<int32_t>(7)`，类型正确无 CTAD 风险。
