## 审查报告：change.md（Iterator 实现）

### 一、整体评估

change.md 描述的是**待实施方案**，源码现状已实现前置工作（C0 根引用统一、typeMethods_ 映射、isAssignable 结构匹配、genIfaceAdapter 通用路径、interfaceImplementations_ 收集），但 Iterator 特定部分（`...` 语法、runtime iterator.h、Sema/CodeGen 特判）**均未实施**。

### 二、P0 Bug（阻断性，必须修复）

**Bug 1：FuncIter 的 T 类型提取语法错误**（C1，[change.md:349-350](file:///d:/you/Aura/change.md#L349-L350)）

```cpp
using T = typename OptionalElem<typename std::invoke_result_t<F&>::result_type>::type;
```

`std::invoke_result_t<F&>` 是 `Optional<T>*`（裸指针），裸指针**没有 `result_type` 成员**，编译失败。

**修复**：先用 `std::remove_pointer_t` 去指针，再提取：
```cpp
using RetType = std::invoke_result_t<F&>;                    // Optional<T>*
using OptType = std::remove_pointer_t<RetType>;               // Optional<T>
using T = typename OptionalElem<OptType>::type;               // T
```
或更简洁，让 `FuncIter` 显式接受 T 模板参数，不做推导：
```cpp
template <typename T, typename F>
struct FuncIter : GcObject, Iterator<T> { ... };
// make_iterator_from<T>(f) 显式传 T
```

[DeclGen.cpp:209-278](file:///d:/you/Aura/src/CodeGen/DeclGen.cpp#L209-L278) 的 genIfaceAdapter 通用路径生成：
```cpp
struct FibIterator final : Iterator<int32_t> {  // ❌ 基类是全局 Iterator，非 aura_rt::Iterator
    ...
```

两个问题：
1. 基类应为 `aura_rt::Iterator<int32_t>`，但通用路径用 `Iterator<int32_t>`（全局命名空间）

### 四、P2 Bug（次要）

**Bug 14：GcRootHandle 不可移动，make_map 退化为拷贝**

[gc.h:84-118](file:///d:/you/Aura/runtime/gc/gc.h#L84-L118) 声明了拷贝构造和 `operator=(const&) = delete`，但**未声明移动构造/移动赋值**。C++ 规则下，声明拷贝构造会抑制默认移动构造。

`make_map` 的 `F(std::move(f))` 若 F 含 GcRootHandle 成员（闭包捕获），会走拷贝构造（深拷贝值 + 独立注册根），而非移动。性能损失，非正确性问题。

**建议**：显式实现移动构造，或 lambda 捕获用 `std::shared_ptr<GcRootHandle>`。

---

**Bug 15：RangeIter 的 T 推导需显式 int32_t**

[change.md:603-606](file:///d:/you/Aura/change.md#L603-L606) 已显式 `make_range<int32_t>` ✓。但 runtime iterator.h 的 `make_range(T start, T end, T step = 1)` 若不显式指定，T 会从字面量推导为 `int`（与 `int32_t` 在多数平台相同，但严格不同）。

change.md C3.1 已显式指定 `<int32_t>` ✓，无 bug。

---

**Bug 16：collect_all 对 GC 指针类型未显式写屏障**

[change.md:377](file:///d:/you/Aura/change.md#L377) `arr->append(o->value_)`。经核查 [array.tcc:222-261](file:///d:/you/Aura/runtime/builtin/array.tcc#L222-L261)，Array::append 内部已用 `gc_write_barrier` 保护 chunk 链接和 chunk_index 更新 ✓。

但 `o->value_` 本身的读取（从 Optional<T>*）若 T 是指针类型，value_ 是 GC 指针。append 参数按值传递（T value），值拷贝指针，无需写屏障 ✓。无 bug。

### 五、设计建议

**建议 1：FuncIter 显式模板参数**

FuncIter 的 T 提取依赖 `OptionalElem` 特化，但 `Optional<T>*` 是指针，无法直接提取 T。建议改为显式模板：
```cpp
template <typename T, typename F>
struct FuncIter : GcObject, Iterator<T> {
    F fn_;
    Optional<T>* next() override { return fn_(); }
};
template <typename T, typename F>
inline FuncIter<T, F>* make_iterator_from(F f) { ... }
```
调用点 CodeGen 显式传 T（从 Sema 推导的 elemType 生成）。

---

**建议 2：Iterator 接口 genInterfaceDecl 跳过机制**

change.md C3.6 用 `if (decl.name == "Iterator") return;` 硬编码特判。但未来若有更多内置接口（如 Stringer/Comparable 也迁移到 runtime），需逐个特判。

**建议**：BuiltinRegistry 新增 `runtimeProvidedInterfaces_` 集合，genInterfaceDecl 遍历时查表跳过：
```cpp
if (BuiltinRegistry::get().isRuntimeProvided(decl.name)) return;
```
