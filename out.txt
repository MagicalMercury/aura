## 1. 核心机制（经 P0 探针修正后的定稿）

### 1.1 逻辑栈指针机制 → ✅ **方案 X 实测成立**（探针 1）

```
每个 Aura 函数入口：push Frame{symbolIdx, line}（RAII FrameGuard，异常路径也 pop）
调用点（仅「可抛点」）：setFrameLine(callLine) —— 更新栈顶帧行号（D1 语义）
抛出点：setFrameLine(throwLine) —— 使栈顶行号 == Error.line（同一值）
出错时：沿逻辑栈自顶向下取帧 → 紧凑帧数组 → 打印时查表格式化
```

- 帧 = **8B**（`{uint32_t symbolIdx; uint32_t line;}`）；帧表 `FrameDesc[]` **全量**（name/file/defLine）；
- **协程挂起/恢复是破坏点** ⇒ **方案 X**：协程帧内保存逻辑栈快照、恢复时还原（探针 1 已验证 6/6）；
- ⚠️ **探针 1 修正的三条**（已回写 plan §4.3.1）：
  1. **截断深度取「整条挂起链的根」**（`min(baseDepth)`），不是当前协程的 `baseDepth`——否则泄漏外层帧、且被挂起协程会被新任务误认作 caller；
  2. **lazy 创建点必须整条栈快照且不截断**（只记一帧不够，跨协程帧全靠它）；
  3. **建议 runtime 禁止裸 `resume()`**，统一 `resumeWithRestore(handle)`（S4 对照证明漏一个恢复入口 ⇒ 静默错 trace + 栈下溢）。

### 1.2 continuation 链与拼接 → ✅ 收敛（探针 2）

- **优先只输出逻辑栈**；**辅段（continuation 链）仅在逻辑栈为空/深度 0 时启用**（无脑拼接实测得到 7 帧且**顺序错乱**，❌ 不可用）；
- 必须拼接时用「辅段末尾 vs 主段前缀**最长重合裁剪**」；连续同点**折叠保计数**；深度上限 32 ⇒ **保留最内 32 帧**。

### 1.3 await_resume / await_suspend 契约（意见 2 + 探针 5/5b）

```cpp
task_promise_base:
  error_ : aura_rt::Error（值，非 exception_ptr）
  unhandled_exception(): catch (const aura_rt::Error& e) { error_ = e; }
                         catch (...) { error_ = make_runtime_error("unknown C++ exception"); }
  await_resume(): if (has_error_) throw error_;      // 抛 Error 值
```

- ✅ **探针 5**：`await_resume` 抛 Error **能被协程体 try/catch 捕获**（6/6，含真挂起+对称转移）；
- ✅ **探针 5b**：`await_suspend` 抛异常**同样可捕获、可值化**（GCC + Clang、`-O0`/`-O2` 一致）⇒ 「协程内抛异常不可捕获」这一族既有结论**全部不成立**；
- 🔴 **探针 5b 挖出的真约束（已写成 plan §4.7 C-1/C-2）**：
  - **C-1**：`await_suspend` **已排程恢复者之后不得再抛**（A7 陈旧排程错位恢复；**A9 已 done 后 resume ⇒ segfault**）⇒ 首选「错误存起来、`await_resume` 抛」；
  - **C-2**：`noexcept` 的 `await_suspend` 抛 ⇒ **`terminate`**（实测）⇒ ⚠️ `task.h:125/185` 现为 `noexcept`，P4 插快照必须 **nothrow**；
  - **P1 必改点**：`win_iocp.cpp:88`（注册回调后抛）、`io.cpp:77-82`（`std::thread` 构造可抛且已 schedule）、`channel.h:32-33/39`（恢复点缺 `done()` 守卫）。

### 1.4 Error 结构扩展（E1 后定稿）

```cpp
struct Error : GcObject {
    GcString* kind, * message;  GcObject* extra;         // 既有
    GcString* file;              // 抛出点文件（编译期字面量）
    int32_t   line;              // 抛出点行号（非指针，不进 ptrFieldOffsets）
    Array<uint64_t>* stack;      // 【E1】紧凑帧：(symbolIdx<<32)|line；nullptr = 无栈
};
```
- `types.cpp:25-36` `_errorPtrFields` **3→5**（kind/message/extra/file/stack），`ptrFieldCount` 同步；
- **OOM 路径必须不解构栈**（`alloc.cpp:498-508`、`mark_sweep.cpp:157-158`、`compact.cpp:389-399`）；
- ⚠️ **既有坑**：`Error` 值所在存储**不在 GC 扫描面**（`registerStackRoots` 全仓仅 `task.cpp:61`）⇒ 生成侧必须显式 `GcRootHandle` 根化。

### 1.5 热路径降级（新增机制，探针 3 验证有效）

- `AURA_ERR_STACK`（默认 `on`）内部两级：**L0 冷**（site 抛出 < **256** 次 ⇒ 完整紧凑栈）/ **L1 热**（≥256 ⇒ **`stack=nullptr`，零分配**）；
- 触发键 = **抛出点 `throwSite`**（逐 `throw` 语句分配编译期 id），**不是 kind**；**单向不回升**、每线程独立计数；
- ✅ **实测**：边界精确（63 有 / 64 无，同形于 255/256）；**site 独立**；降级后与「从来不带栈」**配对等价**（1012.9 vs 992.7 ns/throw）；端到端 10 万次抛出 **507 ms → 140.5 ms（3.6×）**；**降级后 0 分配**。
